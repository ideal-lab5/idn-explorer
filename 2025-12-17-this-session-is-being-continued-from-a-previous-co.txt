⏺ I found the issue. The problem is in the has() method and how Redis sorted
   sets work with JSON members.

  Root Cause:

  The has() check (line 115-124 in randomnessCache.ts) uses zrange with
  byScore: true to check if a block exists. This correctly finds entries
  with that block number (score). However, the issue is that Redis sorted 
  sets allow multiple members with the same score.

  When we call zadd, even though the block number (score) is the same, if
  the JSON string is slightly different (e.g., different timestamp), Redis
  treats it as a different member and adds it.

  Looking at the data:
  - Block 1,945,367 has entries with timestamp differences
  - Block 1,945,360 has 4 entries

  The has() check returns true only if entries exist with that score, but
  the add() method serializes the entire entry including timestamp: 
  Date.now(). If there's any race condition or multiple events for the same
  block, each call creates a unique JSON string member.

  Let me fix this by checking for duplicates more robustly and using a
  unique identifier for each block:

⏺ Done! Here's a summary of what was causing the duplicates and how I fixed
  it:

  Root Cause:
  The original implementation stored full JSON entries (including
  timestamps) as members in a Redis sorted set. Redis sorted sets allow
  multiple members with the same score if the member values are different.
  Since each entry included timestamp: Date.now(), every addition created a
  unique member string even for the same block.

  Fix:
  Changed to a two-key approach:
  1. Sorted set (randomness:cache) - Only stores member keys like
  block:1945367 for ordering
  2. Hash (randomness:data) - Stores the actual entry data keyed by block
  number

  This ensures only one entry per block can exist, regardless of when it was
   added.

  To clear the existing corrupted data:
  After the deployment, you can clear the cache by making a DELETE request:
  curl -X DELETE "https://your-app.vercel.app/api/randomness?confirm=true"

  Or you can clear the Redis keys directly from your Upstash dashboard:
  - Delete randomness:cache
  - Delete randomness:data

  The subscription will automatically repopulate with new (deduplicated)
  data as events occur.
